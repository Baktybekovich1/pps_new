# Выкатка ветки `dev` на прод

Ветка `dev` содержит переход на мультитенантность (организация как арендатор)
и удаление аккаунтов `User`. Изменения накопились задолго до выката, поэтому
здесь записано всё, что нельзя пропустить.

На момент написания прод работает с `master` (`be58acf`) и этими изменениями
не затронут.

---

## 1. Сначала проверьте, не потеряете ли доступ в админку

**Это главный риск выката.** Аккаунтов `User` больше нет — админом может быть
только преподаватель с ролью `ROLE_ADMIN`.

Выполните на проде **до** выката:

```sql
SELECT id, email, roles FROM teacher WHERE roles::text LIKE '%ROLE_ADMIN%';
```

- **Строки есть** — эти люди останутся администраторами, всё в порядке.
- **Пусто** — после выката администрировать систему будет некому.
  Назначьте админа заранее (см. шаг 4) либо сразу после миграции, до того как
  доступ понадобится.

В локальной базе на момент разработки все преподаватели имели только
`ROLE_TEACHER`, а админом был `User`. Если на проде так же — без этого шага
вы останетесь без админки: старая EasyAdmin-панель на `/admin` удалена, а
новая роль ниоткуда не появится.

## 2. Снимите дамп

Миграция `Version20260813120000` **безвозвратно удаляет** таблицы `user` и
`user_offence`. Метод `down()` восстановит только структуру, но не данные.

```bash
pg_dump -U pps pps > pps-before-multitenancy.sql
```

## 3. Выкатка

```bash
composer install --no-dev --optimize-autoloader
php bin/console doctrine:migrations:migrate --no-interaction
php bin/console cache:clear
```

Применятся три миграции:

| Миграция | Что делает | Обратимость |
|---|---|---|
| `Version20260813000000` | Добавляет `organization_id` в 8 таблиц, заполняет выводимое | обратима |
| `Version20260813120000` | Удаляет `user` и `user_offence` | **необратима** |
| `Version20261022000000` | Даёт организацию вопросам; старые ответы, результаты и корректировки отправляет в архив | обратима |

Организации полностью независимы: у каждой своя анкета, свои учебные годы и
свои награды учителей. Всё, что было до выката (общая анкета, общие годы, все
ответы, снимки результатов и экспертные корректировки), становится **архивом**:
строки остаются в базе с `organization_id IS NULL`, и их не видит ни одна
организация, только супер-админ, пока не выбрал организацию. Ничего не удаляется.

Проверить после миграции, что в организациях не осталось старых данных:

```sql
SELECT 'teacher_answer', count(*) FROM teacher_answer WHERE organization_id IS NOT NULL
UNION ALL SELECT 'results_of_year', count(*) FROM results_of_year WHERE organization_id IS NOT NULL
UNION ALL SELECT 'expert_adjustment', count(*) FROM expert_adjustment WHERE organization_id IS NOT NULL;
```

Все три числа должны быть нулевыми.

## 4. Назначьте администраторов

```bash
# админ одной организации (преподаватель должен в ней состоять)
php bin/console app:admin:assign <email> <id организации>

# доступ ко всем организациям
php bin/console app:admin:assign <email> --super
```

Без `--super` никто не сможет создавать и удалять организации — эти операции
теперь требуют `ROLE_SUPER_ADMIN`.

## 5. Заведите каждой организации анкету и год

Сразу после выката у организаций пустые анкеты и нет текущего года, поэтому
учителя не смогут добавить награды («Текущий год не установлен»). Админ
каждой организации в своей админке:

1. создаёт этапы, вопросы и баллы (анкета с нуля);
2. создаёт учебный год — он становится текущим.

Супер-админ делает то же, но сначала выбирает организацию в переключателе
в шапке. Без выбора создание отклоняется с 409.

## 6. Что изменится в поведении

- Данные организаций изолируются автоматически: `OrganizationFilter`
  ограничивает выборки по всем сущностям с `OrganizationOwnedInterface`
  (этапы, вопросы, годы, ответы, институты, эксперты и т. д.). Без выбранной
  организации запрос не видит ничего, а не всё сразу.
- Организацию, за которую действует вошедший пользователь, фронт передаёт в
  заголовке `X-Organization-Id`. Бэкенд сверяет его с местами работы
  аккаунта, чужая организация даёт 403. Без заголовка берётся единственное
  место работы. Учитель нескольких организаций переключается в шапке сайта.
- Публичные страницы рейтинга берут организацию из URL. Годы для них отдаёт
  `/api/organizations/{orgId}/years`, профиль учителя —
  `/api/organizations/{orgId}/user/account/{id}`.
- Новые строки привязываются к выбранной организации (`OrganizationStamper`);
  если организация не выбрана, запрос отклоняется с 409.
- Баллы везде считаются по одному правилу: только незамороженные награды за
  выбранный год плюс награды бессрочных этапов. Раньше итог учителя включал
  замороженные награды и не включал бессрочные, поэтому не совпадал с суммой
  по этапам.
- Админ замораживает и размораживает награды преподавателей своей организации
  через `PATCH /api/admin/teacher/answers/{id}` (`{"active": false|true}`).
  Раньше фронт слал запросы в несуществующие маршруты и модерация не работала.
- Списки учителей (`/api/teacher/`) и директоров (`/api/director/`) теперь
  требуют `ROLE_ADMIN` и показывают только свою организацию. Раньше их отдавали
  целиком, в том числе анонимам. Директором можно назначить только того, кто
  работает в организации института; эксперт оценивает только свою организацию.
- `POST /api/teacher/profile/update` правит только свой профиль. Раньше `id`
  брался из тела запроса, и можно было переписать чужие места работы.
- `/api/rating/institutes` (страница `/rating/institutes`, общий рейтинг
  институтов всех организаций) анонимному посетителю теперь отдаёт пусто:
  баллы существуют только внутри организации. Ссылок на страницу на сайте нет.
- Все маршруты `/api/admin/*` требуют `ROLE_ADMIN`. Раньше часть из них была
  открыта любому авторизованному преподавателю.
- Удалены нерабочие маршруты: `/years/`, `/api/rating/pps`,
  `/api/rating/{comtehno,itec}/pps`, `/expert/add`, `/admin/*`. Все они
  отдавали 500 или не использовались фронтом.
- Пакет `easycorp/easyadmin-bundle` удалён; вместе с ним ушли транзитивные
  `symfony/translation` и `symfony/ux-twig-component`. Если появится нужда в
  переводах, пакет придётся вернуть явно.

## Тесты

```bash
php bin/console --env=test doctrine:database:create
php bin/console --env=test doctrine:migrations:migrate --no-interaction
php vendor/bin/simple-phpunit
```

`tests/Tenant/OrganizationIsolationTest.php` покрывает изоляцию организаций.
Тесты создают свои данные сами — локальная база почти пуста, и полагаться на
неё было бы бессмысленно. Прогоняйте их перед выкатом: именно они поймали
дефект, из-за которого изоляция молча отключалась на весь запрос.
